VMware + Ubuntu 虚拟机部署 Docker + Redis 完整实战指南

前言

在 Windows 环境下使用 Docker，很多人会优先选择 WSL2 方案。但国内网络环境下，WSL 在线安装频繁卡死、内核更新异常、GitHub 连接重置，尤其是部署 Redis 这类常驻后台服务时，子系统稳定性不可控，出问题排查成本很高。

如果你 WSL 安装屡屡碰壁，或者需要一个稳定、可控的环境长期运行中间件服务，VMware + Ubuntu 虚拟机是非常成熟的替代方案：环境隔离完整、网络配置灵活、故障可排查、资源可精准控制，适合长期部署 Redis、MySQL 等常驻服务。

本文从虚拟机创建到 Redis 生产级部署全流程落地，附所有踩坑点与优化方案，全程可复现。

一、前置准备

1.1 配置要求

以 16GB 内存 + i7-13620H 配置为例，完全可以流畅运行，推荐资源分配：

资源项 推荐分配 说明
内存 4096MB（4GB） 跑 Docker + Redis 完全充足
处理器 2核4线程 足够应对常驻服务
磁盘 40GB 以上 后续扩容中间件也够用

CPU 必须支持硬件虚拟化，现在主流笔记本都支持。

1.2 软件准备

  • VMware Workstation：推荐 16/17 Pro 版本，Player 免费版也可满足需求
  • Ubuntu 镜像：优先选择 Ubuntu 22.04 LTS 长期支持版，兼容性和稳定性最好
  • 镜像下载建议走清华、阿里等国内镜像站，避免官网下载速度过慢导致文件损坏

1.3 必做：开启 BIOS 虚拟化

这是虚拟机运行的前提，80% 的启动失败都是因为没开：

  1. 重启电脑，开机时按 F2/Del/F10（依品牌而定）进入 BIOS
  2. 找到 Intel VT-x（Intel CPU）或 AMD SVM（AMD CPU）选项，设置为 Enabled
  3. 保存重启，进入系统后再继续操作

1.4 必做：关闭 Windows Hyper-V

Windows 的 Hyper-V 会和 VMware 抢占虚拟化权限，导致虚拟机无法启动或卡顿：

  1. 按下 Win + R，输入 optionalfeatures.exe 回车
  2. 取消勾选「Hyper-V」「Windows 虚拟机监控平台」「Virtual Machine Platform」
  3. 点击确定，重启电脑生效

二、VMware 创建 Ubuntu 虚拟机

2.1 新建虚拟机

  1. 打开 VMware，点击「创建新的虚拟机」，选择「典型」配置
  2. 选择「安装程序光盘映像文件」，加载下载好的 Ubuntu ISO 镜像
  3. 命名虚拟机，选择保存路径（不要用中文路径，避免后续权限问题）
  4. 磁盘分配：建议 40GB 以上，选择「将虚拟磁盘存储为单个文件」，磁盘读写性能更好
  5. 完成创建，先不要启动，先调整硬件配置

2.2 硬件配置优化

点击「编辑虚拟机设置」，按以下推荐调整：

  • 内存：4096MB（4GB），兼顾虚拟机性能和主机剩余资源
  • 处理器：2 核 4 线程，足够应对 Docker 和常驻服务
  • 网络适配器：默认 NAT 模式即可，主机和虚拟机可互通，虚拟机也能访问外网
  • 显示：显存 1GB，关闭 3D 加速，服务器场景不需要图形性能

2.3 Ubuntu 系统安装

  1. 启动虚拟机，进入安装界面，选择中文简体
  2. 键盘布局选择汉语，点击继续
  3. ⚠️ 关键操作：安装类型选择「正常安装」，取消勾选「安装时下载更新」，避免安装过程中网络超时卡住
  4. 安装类型选择「清除整个磁盘并安装 Ubuntu」，操作的是虚拟磁盘，不会影响主机文件
  5. 时区选择「上海」，设置用户名和密码（密码建议简单好记，本地用无需太复杂）
  6. 等待安装完成，重启进入系统桌面

参数详解

参数 作用
-d 后台守护进程运行，不占用终端
--name redis 容器命名为 redis，方便后续管理
--restart always 异常退出、Docker 重启、虚拟机开机时自动拉起 Redis
-p 6379:6379 端口映射：主机 6379 → 容器内 6379
-v redis-data:/data 数据卷挂载，数据持久化，容器删除数据不丢失
--requirepass 设置连接密码，生产环境必须配置
--appendonly yes 开启 AOF 持久化，每一次写操作都落盘，异常重启数据不丢失

七、常见踩坑排查

7.1 虚拟机无法启动，提示未启用虚拟化

  • 检查 BIOS 是否开启 VT-x/SVM
  • 确认 Windows 功能里 Hyper-V 已完全关闭，重启电脑后再试

7.2 安装 Ubuntu 时界面显示不全，看不到按钮

  • 原因：分辨率太低，安装界面超出显示范围
  • 解决：按住鼠标左键向左拖动安装页面，露出右侧按钮即可

7.3 Docker 拉取镜像很慢

  • 检查是否正确配置了国内镜像加速
  • 验证虚拟机网络：ping baidu.com，不通则检查 NAT 网络设置

7.4 主机连不上虚拟机 Redis

  • 检查虚拟机防火墙是否开放 6379 端口
  • 确认容器启动正常，端口映射配置正确
  • 确认主机和虚拟机网络互通，可以 ping 虚拟机IP 测试

7.5 虚拟机运行越来越卡

  • 定期执行 docker system prune -a 清理无用镜像和容器
  • 关闭 Ubuntu 桌面特效，或后续换成无图形界面的服务器版

八、方案对比：WSL2 vs 虚拟机

方案 稳定性 资源占用 部署难度 适合场景
WSL2 一般 低 高 临时开发、轻量测试
VMware + Ubuntu 高 中等 低 常驻服务、长期部署

如果只是临时跑代码、做轻量测试，WSL2 够用；但如果要长期运行 Redis、MySQL 这类常驻服务，虚拟机方案的稳定性和可控性都要好很多，不会出现子系统异常升级、服务失联、网络重置这类问题。

后续如果需要扩容 MySQL、Nginx、Java 项目，都可以直接在这个 Docker 环境里扩展，复用率很高。
