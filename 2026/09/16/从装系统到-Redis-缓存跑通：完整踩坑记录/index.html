从装系统到 Redis 缓存跑通：完整踩坑记录

从虚拟机搭建到 Redis 缓存跑通：VMware + Ubuntu + Docker 全流程踩坑实录
本文完整记录了从 0 开始在 VMware 中部署 Ubuntu 虚拟机，到 Docker 安装、Redis 容器启动，最终与 Spring Boot 项目联调跑通缓存功能的全流程。全程踩坑密集，从网络配置、镜像加速到 Java 序列化问题逐一记录，所有方案均经过实测验证。
环境说明
表格
类别 版本 / 配置
主机系统 Windows 11
虚拟化软件 VMware Workstation 17 Pro
虚拟机系统 Ubuntu 26.04 LTS
Docker 版本 29.8.1
Redis 版本 7.x
项目框架 Spring Boot 3.x
一、VMware 创建 Ubuntu 虚拟机
1.1 安装配置要点
创建虚拟机时选择「稍后安装操作系统」，避免 Easy Install 自动分区与配置带来的兼容问题；版本选择 Ubuntu 64 位，磁盘分配 40GB 动态扩展，网络模式默认 NAT。
1.2 踩坑：安装目录重命名导致引擎丢失
⚠️ 现象：启动虚拟机时报错 Unable to find the VMX binary，虚拟机完全无法启动。
根因：安装后修改了 VMware 的安装文件夹名称，但注册表与服务中记录的仍是原始绝对路径，导致程序找不到核心执行文件。
解决方案：将文件夹名称改回安装时的原始名称，与注册表路径对齐即可。
经验教训：桌面软件安装完成后不要随意修改安装目录名，所有服务、注册表、驱动关联的都是绝对路径，改名会引发连锁故障。
二、网络配置排障（耗时最长）
网络部分是本次踩坑最多的环节，从桥接模式失效到虚拟网卡丢失，逐一排查解决。
2.1 问题一：桥接模式下获取不到有效 IP
现象：虚拟机 IP 显示为 169.254.x.x 自动私有地址，无法访问外网，主机也 ping 不通虚拟机。
根因：主机使用 WiFi 无线上网，绝大多数无线网卡不支持桥接模式下的 MAC 地址转发，拒绝给虚拟机 MAC 分配 IP 地址。
解决方案：直接改用 NAT 模式（VMnet8）。Windows 主机与虚拟机通过虚拟网卡互通，虚拟机共享主机网络上网，完全满足开发测试需求。
2.2 问题二：NAT 模式依然拿不到 IP
现象：切换 NAT 模式后，虚拟机依然是 169.254 段地址，ip a 看不到正常的内网 IP。
根因：之前修改 VMware 安装目录，导致 VMnet1、VMnet8 虚拟网卡驱动信息损坏，虚拟交换机工作异常。
解决方案：
打开 VMware → 编辑 → 虚拟网络编辑器
点击右下角「更改设置」获取管理员权限
点击「还原默认设置」，自动重建所有虚拟网卡与网络配置
等待重建完成后重启虚拟机
2.3 问题三：NetworkManager 缓存失效状态
现象：虚拟网卡恢复后，Ubuntu 依然无法获取 IP，网络状态停留在失败缓存。
解决方案：重建网络连接，清除旧缓存：
bash

删除旧的失效连接

sudo nmcli connection delete “netplan-ens33”

新建自动获取 IP 的以太网连接

sudo nmcli connection add type ethernet ifname ens33 con-name “ens33-auto” ipv4.method auto

启用连接

sudo nmcli connection up “ens33-auto”
2.4 问题四：网络连通但域名解析失败
现象：能 ping 通公网 IP，但 ping baidu.com 报域名解析错误，apt 无法下载软件。
解决方案：手动配置 DNS 服务器：
bash

修改连接的 DNS 配置

sudo nmcli connection modify “ens33-auto” ipv4.dns “8.8.8.8 114.114.114.114”

重启连接生效

sudo nmcli connection up “ens33-auto”
三、Docker 安装与镜像加速
3.1 安装选择
尝试使用阿里云 docker-ce 源下载速度极慢，改用 Ubuntu 官方源的 docker.io 包，安装更稳定：
bash
sudo apt update
sudo apt install -y docker.io
3.2 踩坑：阿里云个人镜像加速器停服
⚠️ 现象：配置阿里云个人加速器地址后，拉取镜像一直超时，返回 403 错误。
根因：阿里云容器镜像服务 ACR 个人免费加速器已调整下线，旧地址不再提供服务。
解决方案：替换为国内公共镜像加速站，在 /etc/docker/daemon.json 中配置：
bash
echo ‘{
“registry-mirrors”: [
“https://docker.m.daocloud.io“,
“https://docker.1ms.run“,
“https://dockerpull.com“
],
“log-driver”: “json-file”,
“log-opts”: {
“max-size”: “100m”,
“max-file”: “3”
}
}’ | sudo tee /etc/docker/daemon.json
重启 Docker 生效：
bash
sudo systemctl daemon-reload
sudo systemctl restart docker
3.3 用户权限配置
将当前用户加入 docker 用户组，避免每次执行命令都要加 sudo：
bash
sudo usermod -aG docker $USER
注销重新登录后生效。
四、Redis 容器部署与连通验证
4.1 启动 Redis 容器
拉取镜像并启动生产级容器，配置端口映射与开机自启：
bash

拉取镜像

docker pull redis:7

启动容器

docker run -d
–name myredis
–restart always
-p 6379:6379
redis:7
redis-server
–appendonly yes
4.2 主机连通验证
查看虚拟机 IP 地址后，在 Windows 主机测试端口连通性：
powershell

测试端口连通性

Test-NetConnection 192.168.110.128 -Port 6379
Spring Boot 项目配置文件中填写虚拟机地址：
yaml
spring:
data:
redis:
host: 192.168.110.128
port: 6379
五、Spring Boot 集成 Redis 缓存
5.1 缓存注解配置
针对高频查询接口添加缓存注解，写操作同步清除缓存保证数据一致性：
表格
接口场景 注解配置 缓存前缀
热门攻略列表 @Cacheable(value=”strategy:hot”, key=”#limit”) strategy:hot
首页轮播图 @Cacheable(value=”strategy:banner”, key=”#limit”) strategy:banner
城市列表 @Cacheable(value=”strategy:cities”, key=”‘all’”) strategy:cities
攻略发布、编辑、删除、上下线等写操作，添加 @CacheEvict 注解清空对应缓存。
5.2 踩坑：LocalDateTime 序列化失败
⚠️ 现象：访问带缓存的接口报 500 错误，Redis 中没有生成缓存数据。
根因：自定义 RedisConfig 中手动 new ObjectMapper() 没有注册 Java 8 时间模块，LocalDateTime 类型字段序列化失败。
解决方案：在 Redis 配置类中完善 ObjectMapper 配置：
java
运行
@Configuration
public class RedisConfig {

@Bean
public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
    RedisTemplate<String, Object> template = new RedisTemplate<>();
    template.setConnectionFactory(factory);

    Jackson2JsonRedisSerializer<Object> serializer = new Jackson2JsonRedisSerializer<>(Object.class);
    ObjectMapper om = new ObjectMapper();
    // 注册 Java 8 时间模块
    om.registerModule(new JavaTimeModule());
    // 关闭时间转时间戳
    om.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
    serializer.setObjectMapper(om);

    template.setKeySerializer(new StringRedisSerializer());
    template.setValueSerializer(serializer);
    template.setHashKeySerializer(new StringRedisSerializer());
    template.setHashValueSerializer(serializer);
    return template;
}

@Bean
public CacheManager cacheManager(RedisConnectionFactory factory) {
    // 同上，cacheManager 也需要使用配置好的序列化器
    // ...
}

}
注意：redisTemplate 和 cacheManager 两个 Bean 都要使用正确配置的序列化器，否则依然会报错。

Redis 中生成对应缓存键 strategy:hot::5 ✅
重复请求同一接口，响应耗时大幅下降，缓存生效 ✅

七、踩坑经验总结
表格
问题类型 核心教训
VMware 目录改名 软件安装目录不要随意重命名，改了就还原，不要硬修注册表
WiFi 桥接模式 无线网卡基本不支持桥接，开发测试直接用 NAT 模式
虚拟网卡丢失 网络异常先还原虚拟网络默认设置，比重装驱动快
网络状态缓存 nmcli 重建连接比重启虚拟机、反复插拔网卡更高效
阿里云加速器 个人免费加速器已停服，换用公共镜像站
时间序列化 自定义 ObjectMapper 必须注册 JavaTimeModule，否则 LocalDateTime 必报错
