从装系统到 Redis 缓存跑通：完整踩坑记录

环境：Windows 11 主机 + VMware Workstation 17 Pro + Ubuntu 26.04 LTS + Docker 29.8.1 + Redis 7 + Spring Boot 3

任务一：VMware 创建 Ubuntu 虚拟机

关键决策

  • 选「稍后安装操作系统」而不是 Easy Install（避免新版 Ubuntu 安装器兼容问题）
  • 版本选 Ubuntu 64-bit
  • 磁盘设 40GB（动态分配，不占满）
  • 网络模式选 NAT（WiFi 网卡不支持桥接，详见任务二）

踩坑：VMware 安装目录改名导致引擎丢失

现象：开机报 Unable to find the VMX binary 'D:\网安\vmware-vmx.exe'

根因：之前把 VMware 安装文件夹从 网安 改名为 Vmware，但注册表里记录的还是老路径。

解决：把文件夹名改回 网安，注册表路径对上即可。

教训：软件安装目录装完后不要改名，所有配置/服务都记录着绝对路径。

任务二：网络配置（耗时最长，踩坑最多）

问题 1：虚拟机拿到 169.254.x.x 地址

原因：VMware 桥接模式下，WiFi 芯片/驱动只接收发给自己 MAC 的包，拒绝转发给虚拟机 MAC → DHCP 拿不到 IP。

解决：改用 NAT 模式（VMnet8），Windows 能直接访问虚拟机，完全满足开发需求。

问题 2：NAT 模式下依然拿不到 IP

根因：Windows 的虚拟网卡（VMnet1/VMnet8）丢失了——因为之前重命名 VMware 安装文件夹，导致虚拟网卡驱动信息损坏。

解决：VMware → 编辑 → 虚拟网络编辑器 → 更改设置 → 还原默认设置，重建 VMnet0/1/8。

任务五：Spring Boot Redis 缓存开发

缓存注解

接口 注解 缓存名
热门攻略 @Cacheable(value="strategy:hot", key="#limit") strategy:hot
轮播图 @Cacheable(value="strategy:banner", key="#limit") strategy:banner
城市列表 @Cacheable(value="strategy:cities", key="'all'") strategy:cities

写操作（发布/编辑/删除/上下线）加 @CacheEvict 清空缓存，保证一致性。

关键坑：LocalDateTime 序列化失败

现象：访问热门攻略接口 500，Redis 为空。

根因：RedisConfig 里手动 new ObjectMapper() 没有注册 Java 8 时间模块，序列化 Strategy 的 LocalDateTime 字段报错。

修复：

redisTemplate 和 cacheManager 两个 Bean 都要改。

验证结果

  1. 访问 /strategy/hot?limit=5 返回 JSON 数据 ✅
  2. redis-cli keys "*" 出现 strategy:hot::5 ✅

经验总结

问题类型 教训
VMware 改名 安装目录绝不改名，改了就还原
WiFi 桥接 无线网卡基本不支持桥接，直接用 NAT
虚拟网卡丢失 还原默认设置一键重建
网络状态缓存 nmcli 重建连接比反复重启更有效
阿里云加速器 已停服，换 DaoCloud/1ms.run 公共源
LocalDateTime 自定义 ObjectMapper 必须注册 JavaTimeModule
