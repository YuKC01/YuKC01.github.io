VMware + Ubuntu 虚拟机部署 Docker + Redis 完整实战指南

前言

在 Windows 环境下使用 Docker，很多人会优先选择 WSL2 方案。但国内网络环境下，WSL 在线安装频繁卡死、内核更新异常、GitHub 连接重置，尤其是部署 Redis 这类常驻后台服务时，子系统稳定性不可控，出问题排查成本很高。

如果你 WSL 安装屡屡碰壁，或者需要一个稳定、可控的环境长期运行中间件服务，VMware + Ubuntu 虚拟机是非常成熟的替代方案：环境隔离完整、网络配置灵活、故障可排查、资源可精准控制，适合长期部署 Redis、MySQL 等常驻服务。

本文从虚拟机创建到 Redis 生产级部署全流程落地，附所有踩坑点与优化方案，全程可复现。

Docker 入门实战：Windows 环境下部署 Redis 完整指南

前言
在 Windows 上做开发时，安装 Redis 经常会遇到环境配置繁琐、服务管理麻烦、版本切换困难等问题。使用 Docker 容器化部署可以完美解决这些痛点，一键启动、环境隔离、数据持久化，非常适合本地开发和常驻后台使用。
一、Docker 核心概念
三个最核心的基础概念，理解后就能上手大部分操作：
镜像（Image）
相当于软件的「安装包」，比如 Redis 官方镜像就是打包好的完整 Redis 程序，包含所有依赖和运行环境，只读不可修改。
容器（Container）
镜像运行起来的实例，相当于「安装好并正在运行的软件」。每个容器互相隔离，拥有独立的文件系统和网络，删除容器不会影响本地系统。
仓库（Registry）
存放镜像的「软件商店」，最常用的是 Docker Hub，官方的 Redis、MySQL、Nginx 等镜像都可以从上面拉取。
二、为什么用 Docker 跑 Redis
对比 Windows 原生安装 Redis，优势非常明显：
一键部署，告别繁琐配置：不用找安装包、配环境变量、注册系统服务，一条命令就能启动完整可用的 Redis。
环境隔离，不污染系统：Redis 的配置、数据、日志都在容器内，卸载就是删除容器，不会留下残留文件和注册表项。
版本随意切换：想切换 Redis 6、7 或最新版，只需要更换镜像标签，几秒即可完成，无需卸载重装。
开机自启，稳定省心：配置重启策略后，电脑开机 Docker 会自动拉起 Redis，和系统服务效果一致。
资源可控：可以精确限制 Redis 占用的 CPU、内存上限，避免占用过多系统资源。
三、环境准备与安装
3.1 WSL 2 前置要求
Docker Desktop for Windows 默认基于 WSL 2 运行，这是官方推荐的标准方案，性能优于 Hyper-V。
版本要求：WSL 2 最低版本 2.1.5，2.7.14 及以上稳定版均可完美兼容。
安装完成后必须重启电脑才能生效。
3.2 安装 Docker Desktop
从 Docker 官网下载 Windows 版安装包。
双击安装，配置页务必勾选「Use WSL 2 instead of Hyper-V」，不要选择 Windows 容器。
安装完成后重启电脑。
3.3 基础配置优化
启动 Docker Desktop，点击右上角设置图标：
General：确认「Use the WSL 2 based engine」已勾选（默认开启）。
Resources → WSL Integration：确保你的 WSL 发行版开关已打开，点击 Apply & restart 生效。
Resources → Advanced：可手动调整 WSL 的内存、CPU 上限，16GB 内存建议分配 4GB 给 WSL，跑 Redis 完全够用。
3.4 验证安装
打开 Windows 终端（PowerShell / CMD 均可），输入：
cmd
docker –version
输出版本号（如 Docker version 27.x.x）即说明安装成功。
四、Docker 部署 Redis 完整步骤
4.1 拉取官方镜像
将 Redis 镜像拉取到本地：
cmd
docker pull redis:latest
redis:latest 表示最新稳定版，也可指定版本，例如 redis:7-alpine（轻量版，体积更小）。
4.2 最简启动（临时测试用）
快速启动验证环境是否正常：
cmd
docker run -d –name redis-test -p 6379:6379 redis:latest
注意：此版本无密码、无数据持久化，容器删除后数据会丢失，仅用于临时测试。
4.3 生产级启动（推荐长期使用）
带密码验证、数据持久化、开机自启，数据不会丢失，适合日常开发常驻使用。
第一步：创建数据卷
Docker 卷用于持久化存储容器数据，容器删除后卷内数据依然保留：
cmd
docker volume create redis-data
第二步：执行启动命令
cmd
docker run -d ^
–name redis ^
–restart always ^
-p 6379:6379 ^
-v redis-data:/data ^
redis:latest ^
redis-server ^
–requirepass yourpassword123 ^
–appendonly yes
说明：Windows CMD 用 ^ 换行，PowerShell 用 ` 换行，也可以整合成一行执行。
参数详解
表格
参数 作用
-d 后台运行容器，不占用终端窗口
–name redis 给容器命名为 redis，方便后续管理
–restart always 开机自启：Docker 启动、电脑重启后自动拉起 Redis
-p 6379:6379 端口映射：本地 6379 端口 → 容器内 6379 端口
-v redis-data:/data 数据挂载：将数据卷挂载到容器内 Redis 的数据目录
–requirepass yourpassword123 设置 Redis 连接密码
–appendonly yes 开启 AOF 持久化，异常重启数据不丢失
4.4 验证运行状态
两种方式验证：
命令行验证
cmd
docker exec -it redis redis-cli -a yourpassword123 ping
返回 PONG 即为正常运行。
客户端连接
使用 Redis 可视化工具（如 Another Redis Desktop Manager），连接地址 127.0.0.1，端口 6379，输入密码即可连接。
五、Redis 容器日常管理命令
cmd

查看运行中的容器

docker ps

停止 Redis

docker stop redis

启动 Redis

docker start redis

重启 Redis

docker restart redis

查看运行日志

docker logs redis

进入 Redis 命令行

docker exec -it redis redis-cli -a yourpassword123

删除容器（数据卷不会被删除，数据依然保留）

docker rm -f redis
六、关键注意事项
数据安全
只要挂载配置不变，删除容器后重新执行启动命令，数据会自动恢复。
定期备份：执行 docker exec redis BGSAVE，会在数据卷中生成 RDB 备份文件。
内存占用
Redis 本身非常轻量，正常运行仅占用几十 MB 内存，加上 WSL 开销总共几百 MB，资源占用极低。
网络安全
默认只有本地电脑能连接，外网无法访问。如果需要局域网访问，启动命令加上 –bind 0.0.0.0 参数即可。
图形化管理
Docker Desktop 左侧点击 Containers，即可看到所有容器，可直观查看日志、启停容器、进入终端，无需记忆命令。
七、硬件配置适配建议
以 16GB 内存 + 13 代 i7 配置为例：
WSL2 建议分配 4GB 内存、4 核 CPU，跑 Redis 完全充足，剩余资源留给 Windows 主系统。
可通过用户目录下的 .wslconfig 文件手动限制资源，示例配置：
ini
[wsl2]
memory=4GB
processors=4
保存后执行 wsl –shutdown 重启 WSL 生效。
进阶：Docker Compose 管理
如果后续需要同时管理 MySQL、Nginx 等多个服务，推荐使用 Docker Compose，通过一个配置文件统一管理所有服务，启动停止一键操作。
